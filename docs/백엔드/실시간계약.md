# 실시간 계약 (WebSocket)

- 엔드포인트: 웹을 서빙하는 것과 **같은 origin** 의 `/ws`. (`ws://host/ws`, HTTPS 면 `wss://`)
- 모든 메시지는 UTF-8 JSON 객체 한 개이고 `t` 필드로 종류를 구분한다.
- 서버는 받은 모든 메시지를 경계에서 검증한다. 형식이 어긋나면 `error` 를 보내고 그 메시지는 버린다.
- 프레임 64KB 초과, 텍스트가 아닌 프레임, 초당 60개를 넘는 메시지는 거절한다(`RATE_LIMITED` 후 종료).

## 클라이언트 → 서버

| `t` | 필드 | 설명 |
| --- | --- | --- |
| `create` | `nickname` | 새 방을 만들고 왼쪽 자리에 앉는다 |
| `join` | `nickname`, `code` | 코드로 방에 참가한다 |
| `practice` | `nickname` | 봇 상대 연습 방을 만든다 |
| `resume` | `token` | 끊긴 세션을 같은 자리로 되돌린다 |
| `input` | `seq`, `ax`, `ay`, `kick` | 입력 상태. `ax`/`ay` 는 -1~1, `kick` 은 누르고 있는지 여부 |
| `rematch` | — | 경기 종료 후 재경기 준비 토글 |
| `leave` | — | 방에서 나간다 |
| `ping` | `ts` | 지연 측정 |

`nickname` 은 1~12자, 제어문자 불가. `code` 는 6자 `[A-Z0-9]`(소문자는 대문자로 정규화).
`seq` 는 단조 증가 정수이며, 과거 `seq` 입력은 버린다.

## 서버 → 클라이언트

| `t` | 주요 필드 | 설명 |
| --- | --- | --- |
| `joined` | `token`, `code`, `side`, `mode` | 자리 배정 결과. `token` 은 재접속용이며 화면에 노출하지 않는다 |
| `room` | `code`, `phase`, `players[]`, `score`, `timeLeftMs`, `countdownMs`, `result` | 방 메타 상태. 변할 때만 보낸다 |
| `snapshot` | `tick`, `ts`, `ball`, `players[]`, `score`, `phase`, `timeLeftMs`, `countdownMs` | 20Hz 경기 상태 |
| `event` | `kind`, 부가 필드 | `goal` `kickoff` `matchEnd` `opponentJoined` `opponentLeft` `opponentDisconnected` `opponentReconnected` |
| `error` | `code`, `message` | 아래 표 참고 |
| `pong` | `ts` | `ping` 의 `ts` 를 그대로 돌려준다 |

### phase

`waiting` → `countdown` → `playing` → (`goal` → `countdown` → `playing`)\* → `ended`

### error code

`BAD_MESSAGE` `INVALID_NICKNAME` `ROOM_NOT_FOUND` `ROOM_FULL` `NOT_IN_ROOM` `TOKEN_INVALID` `RATE_LIMITED` `SERVER_BUSY`

## 방 수명

- 두 자리가 모두 비면 60초 뒤 방을 지운다.
- 활동이 20분 없으면 방을 지운다.
- 접속이 끊긴 선수의 자리는 30초 동안 유지된다. 그 사이 같은 `token` 으로 `resume` 하면 점수와 경기 시간이 이어진다.
- 서버 전체 방 수는 500개로 제한한다. 초과 시 `SERVER_BUSY`.

## 공개 HTTP 면

| 경로 | 내용 |
| --- | --- |
| `GET /healthz` | `{"status":"ok","uptimeMs":…,"rooms":…}` |
| 그 외 | `app/web` 빌드 산출물 (SPA fallback) |

상태를 바꾸는 치트·디버그 엔드포인트는 두지 않는다.
