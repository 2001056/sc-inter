# 실시간 계약 (WebSocket)

이 문서와 `app/api/src/protocol.ts` 가 서버-프런트 공동 계약이다. 타입 정의의 원본은 `protocol.ts` 이며, 이 문서는 그 의미와 규칙을 설명한다.

- 엔드포인트: 웹을 서빙하는 것과 **같은 origin** 의 `/ws`. (`ws://host/ws`, HTTPS 면 `wss://`)
- 모든 메시지는 UTF-8 JSON 객체 한 개이고 `t` 필드로 종류를 구분한다.
- 서버는 받은 모든 메시지를 경계에서 검증한다. 형식이 어긋나면 `error` 를 보내고 그 메시지는 버린다.
- 프레임 64KB 초과, 텍스트가 아닌 프레임, 초당 60개를 넘는 메시지는 거절한다(`RATE_LIMITED` 후 종료).
- **입력은 키가 아니라 의도를 보낸다.** 어떤 키를 어떤 의도에 묶을지는 프런트가 정하므로 키 매핑을 바꿔도 이 계약은 바뀌지 않는다.

## 좌표계와 단위

| 항목 | 규약 |
| --- | --- |
| 길이 | 미터. 경기장 56m × 34m, 골대 폭 5.5m |
| 좌표 | `x` = 길이 방향(0 = 왼쪽 골라인), `y` = 폭 방향. 3D 는 `(x, y) -> (x, z)` |
| 속도 | m/s |
| 각도 | 라디안. `facing = atan2(dy, dx)` 규약 |
| 시간 | 밀리초 |

경기장 치수·인원·쿨다운 상한은 `joined` 의 `pitch` 로 내려가므로 프런트에서 하드코딩하지 않는다.

## 팀과 선수

- 한 팀은 3명이고 id 는 `L1 L2 L3` / `R1 R2 R3` 로 경기 내내 고정된다. 역할은 `defender` `mid` `forward` 순이다.
- 사람은 팀마다 한 명만 접속하며, 그 순간 조작 중인 선수는 `snapshot.controlled[side]` 와 각 선수의 `controlled` 플래그로 알 수 있다.
- 나머지 선수는 서버 AI 가 움직인다. 사람이 없는 팀(연습 모드)은 세 명 모두 AI 이고 `human: false` 로 내려간다.

## 클라이언트 → 서버

| `t` | 필드 | 설명 |
| --- | --- | --- |
| `create` | `nickname` | 새 방을 만들고 왼쪽 팀을 맡는다 |
| `join` | `nickname`, `code` | 코드로 방에 참가한다 |
| `practice` | `nickname` | AI 팀을 상대하는 연습 방을 만든다 |
| `resume` | `token` | 끊긴 세션을 같은 자리로 되돌린다 |
| `input` | 아래 표 | 조작 중인 선수에게 적용된다 |
| `rematch` | — | 경기 종료 후 재경기 준비 |
| `leave` | — | 방에서 나간다 |
| `ping` | `ts` | 지연 측정 |

### input 필드

| 필드 | 형태 | 의미 |
| --- | --- | --- |
| `seq` | 정수, 단조 증가 | 과거 `seq` 는 버린다 |
| `ax`, `ay` | -1~1 | 월드 좌표 이동 방향. 길이가 1을 넘으면 서버가 정규화한다 |
| `sprint` | 누르는 동안 `true` | 달리기 |
| `shoot` | 누르는 동안 `true` | `true → false` 가 되는 순간 충전량만큼 찬다 |
| `pass` | 누르는 순간 한 번 `true` | 앞쪽 동료에게 땅볼 패스 |
| `tackle` | 누르는 순간 한 번 `true` | 슬라이딩 태클 |
| `skillDir` | `{x, y}` 또는 `null` | 개인기. 월드 좌표 방향을 누르는 순간 한 번만 담는다 |
| `switchPlayer` | 누르는 순간 한 번 `true` | 조작 선수 수동 전환 |

- `nickname` 1~12자, 제어문자 제거. `code` 6자 `[A-Z0-9]`(소문자는 대문자로 정규화).
- 입력은 변할 때마다, 그리고 최소 20Hz 로 보내는 것을 권장한다.

### 개인기 방향 해석 — 공격 방향 기준(attack-relative)

`skillDir` 은 **월드 좌표** 벡터로 보내고, 서버가 그 팀이 공격하는 방향을 기준으로 앞/뒤/좌/우를 판정한다.
왼쪽 팀은 `+x`, 오른쪽 팀은 `-x` 가 "앞"이다. 카메라 기준이 아니므로 프런트는 화면 방향을 월드 방향으로 바꿔서 보내면 된다.

| 판정 | 결과 |
| --- | --- |
| 앞 (`dot(dir, attackDir) > 0.5`) | `stepover` |
| 뒤 (`< -0.5`) | `dragback` |
| 그 외, 공격 방향 기준 왼쪽 | `feintLeft` |
| 그 외, 오른쪽 | `feintRight` |

## 서버 → 클라이언트

| `t` | 주요 필드 | 설명 |
| --- | --- | --- |
| `joined` | `token`, `code`, `side`, `mode`, `pitch` | 자리 배정 결과. `token` 은 재접속용이며 화면에 노출하지 않는다 |
| `room` | `code`, `mode`, `phase`, `players[]`, `score`, `timeLeftMs`, `countdownMs`, `result` | 방 메타 상태. 변할 때만 보낸다 |
| `snapshot` | `tick`, `ts`, `phase`, `ball`, `players[]`, `score`, `timeLeftMs`, `countdownMs`, `controlled`, `passTarget`, `stats` | 20Hz 경기 상태 |
| `event` | `kind` + 부가 필드 | 아래 표 |
| `error` | `code`, `message` | 아래 표 |
| `pong` | `ts` | `ping` 의 `ts` 를 그대로 돌려준다 |

### pitch (joined)

`length` `width` `goalWidth` `goalDepth` `playerRadius` `playerHeight` `ballRadius` `teamSize`
`skillCooldownMs`(2600) `tackleCooldownMs`(5200) `shootChargeMs`(700)

쿨다운 게이지는 `1 - cooldowns.skill / pitch.skillCooldownMs` 로 그린다.

### snapshot 의 선수 필드

| 필드 | 설명 |
| --- | --- |
| `id`, `side`, `role` | 고정 식별자와 팀·역할 |
| `controlled` | 그 팀의 사람이 지금 조작 중인 선수인지 |
| `human` | 사람이 있는 팀 소속인지 |
| `x`, `y`, `vx`, `vy` | 위치·속도 |
| `facing` | 바라보는 방향(라디안) |
| `charge` | 0~1 슛 충전량 |
| `stamina` | 0~1 남은 스태미나 |
| `dribbling` | 공을 몰고 있는지 |
| `skill`, `skillMs` | 진행 중인 개인기와 남은 시간 |
| `cooldowns` | `{ skill, tackle }` 남은 쿨다운(ms) |
| `anim` | `idle` `run` `sprint` `dribble` `shoot` `pass` `stepover` `feintLeft` `feintRight` `dragback` `tackle` `prone` `celebrate` |

- `ball` 에는 `x y vx vy spin` 과 소유자 `ownerId`(없으면 `null`)가 있다.
- `controlled` 는 `{ left, right }` 로 각 팀의 조작 선수 id.
- `passTarget` 은 `{ left, right }` 로, 그 팀의 조작 선수가 지금 패스하면 받을 동료 id(없으면 `null`). 화면에서 하이라이트에 쓴다.

### snapshot 의 stats

`stats` 는 `{ left: TeamStats, right: TeamStats }` 이고 모든 스냅샷(`countdown` `goal` `ended` 포함)에 항상 들어 있다.

| 필드 | 형태 | 의미 |
| --- | --- | --- |
| `shots` | 정수 | 발이 닿은 유효한 슛 수 |
| `passes` | 정수 | 발이 닿은 유효한 패스 수 |
| `completedPasses` | 정수 | 받기로 한 동료가 처음 공을 잡은 패스 수(≤ `passes`) |
| `possessionMs` | 정수(ms) | `playing` 중 그 팀이 공을 소유한 누적 시간 |

점유율은 `possessionMs / (left + right)` 로 프런트가 계산한다(합이 0 이면 표시하지 않는다). 득점 뒤 킥오프에서는 유지되고 재경기에서 0 으로 돌아간다. 세부 판정은 `시뮬레이션.md` 의 경기 기록 절에 있다.

`anim` 은 서버가 확정하므로 두 브라우저가 같은 동작을 본다. 프런트는 이 값으로 애니메이션 클립을 고르고, 클립 사이 블렌딩만 스스로 처리한다.

| --- | --- | --- |
| `goal` | `side`, `scorerId`, `score` | 득점 연출 |

| `control` | `side`, `playerId` | 조작 선수가 바뀌었을 때 |
| `opponentJoined` | `nickname` | 상대 입장 |
| `opponentLeft` | — | 상대 퇴장(자리 비움) |

### phase

`waiting` → `countdown` → `playing` → (`goal` → `countdown` → `playing`)\* → `ended`

### error code

`BAD_MESSAGE` `INVALID_NICKNAME` `ROOM_NOT_FOUND` `ROOM_FULL` `NOT_IN_ROOM` `TOKEN_INVALID` `RATE_LIMITED` `SERVER_BUSY`

## 방 수명

- 사람 자리가 모두 비면 60초 뒤 방을 지운다.
- 활동이 20분 없으면 방을 지운다.
- 접속이 끊긴 선수의 자리는 30초 동안 유지된다. 그 사이 같은 `token` 으로 `resume` 하면 점수와 경기 시간이 이어진다.
- 서버 전체 방 수는 500개로 제한한다. 초과 시 `SERVER_BUSY`.
