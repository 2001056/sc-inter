# 3D 자산과 라이선스

## 결론

이 게임의 **3D 자산은 전부 코드가 런타임에 만든다**. 게임용 외부 모델 파일
(`.glb`, `.gltf`, `.fbx`)이나 래스터 텍스처 이미지를 저장소에 두지 않았고, 실행 중에
외부 CDN 으로 나가는 요청도 없다. 즉 **이번 작업으로 제3자의 3D 저작물을 새로
들여오지 않았다**.

라이선스 표기가 필요 없다는 뜻은 아니다. `app/web` 은 React, React DOM, three.js,
Vite 등 여러 오픈소스 패키지 위에서 돈다. 각 패키지의 라이선스는 그대로 유효하고
`app/web/package.json` 과 lockfile 이 그 목록이며, 배포할 때의 고지 의무는 이 문서가
아니라 그 의존성 목록을 기준으로 따로 판단한다. 이 문서가 말하는 범위는 **게임에
등장하는 3D 모델·애니메이션·텍스처**뿐이다.

3D 렌더링에는 [three.js](https://github.com/mrdoob/three.js)(MIT)를 쓴다. 다만 three.js
저장소의 **예제 자산**(`examples/models/**`)은 라이선스가 개별적으로 다르고 일부는
출처가 불분명해 **쓰지 않았다**.

| 대상 | 만드는 곳 | 방식 |
| --- | --- | --- |
| 선수 메시 | `app/web/src/three/playerModel.ts` | 단면을 훑은 관 + 타원체를 합쳐 만든 스킨 메시 |
| 선수 뼈대 | `app/web/src/three/rig.ts` | 관절 위치 표에서 `THREE.Bone` 계층을 생성 |
| 동작 | `app/web/src/three/animation.ts` | 매 프레임 뼈 회전을 계산(클립 파일 없음) |
| 잔디·라인·유니폼·공·골네트·관중석 | `app/web/src/three/textures.ts` | `<canvas>` 에 그려 `CanvasTexture` 로 업로드 |
| 경기장·골대·조명·밤하늘 | `app/web/src/three/pitch.ts` | three.js 기본 도형과 셰이더 |

## 왜 기성 모델을 쓰지 않았나

"작은 원형 토큰이 아니라 진짜 사람처럼 생긴 축구 선수" 가 요구사항이었으므로 먼저
재배포 가능한 무료 human glTF 를 찾아봤다. 검토 결과와 판단은 아래와 같다.

| 후보 | 라이선스 | 왜 쓰지 않았나 |
| --- | --- | --- |
| Khronos `glTF-Sample-Assets` 의 CesiumMan | CC BY 4.0 (© 2017 Cesium) | 재배포는 가능하지만 폴리곤이 매우 적고 얼굴·유니폼 디테일이 없다. 가슴에 Cesium 로고가 박혀 있고 걷기 클립 하나뿐이라 축구 선수로 쓸 수 없다 |
| Quaternius 캐릭터 팩 | 공개 페이지는 CC0 이나, 최신 자체 라이선스(QAL)의 재배포 제한과 충돌 | 공개 저장소에 넣어도 되는지가 불분명하다고 판정되어 사용을 보류했다 |
| three.js 예제의 Soldier / Xbot 등 | 불분명(Mixamo 유래로 보임) | 출처·재배포 조건을 확인할 수 없어 제외 |
| Mixamo | 계정 필요, 원본 자산 재배포 제한 | 공개 저장소에 넣을 수 없다 |

공통적으로 걸린 문제가 하나 더 있다. 이 게임에는 **스텝오버·바디페인트·드래그백·
슬라이딩 태클** 동작이 필요한데, 위 후보 중 어느 것도 이런 클립을 갖고 있지 않다.
기성 모델을 쓰더라도 뼈 애니메이션은 결국 직접 만들어야 했다.

그래서 메시까지 코드로 만드는 쪽을 골랐다. 이렇게 하면

- 재배포 조건이 불분명한 3D 자산을 저장소에 들이지 않아도 된다. 의존성 패키지의
  라이선스 확인은 그대로 남지만, 적어도 모델·애니메이션 쪽 불확실성은 없앴다.
- 번들에 게임용 바이너리 자산이 들어가지 않는다(전체 JS 약 780KB, gzip 약 217KB).
- 팀 색·등번호·피부색·머리색·키를 런타임에 바꿀 수 있다. 서버가 `playerHeight` 를
  바꾸면 프런트는 고칠 것이 없다.
- 동작을 서버 상태(충전량, 개인기 남은 시간, 속도)에 직접 연결할 수 있다.

## 선수 모델의 구조

기준 키는 1.80m 이고, 관절 높이는 실제 성인 남성 비율을 따른다(머리 하나가 키의
약 1/7.5). 서버가 알려 준 `PitchInfo.playerHeight` 에 맞춰 바깥 그룹에서 한 번만
크기를 조정하므로, 경기장 규격이 바뀌어도 비율이 유지된다.

- **뼈대 21개**: 골반 – 척추 – 가슴 – 윗가슴 – 목 – 머리, 좌우 어깨/위팔/아래팔/손,
  좌우 허벅지/정강이/발/발끝.
- **스킨 가중치**: 정점에서 각 뼈 구간까지의 거리를 재서 가장 가까운 두 개에 나눠
  준다. 관절 바로 옆에서는 두 뼈가 비슷한 거리라 자연스럽게 반반씩 섞이고, 무릎과
  팔꿈치가 접힐 때 면이 끊기지 않는다.
- **부위별 재질 8종**: 피부, 상의, 반바지, 양말, 축구화, 밑창, 머리카락, 눈(흰자/동공).

### 여기서 한 번 크게 틀렸던 것

메시 생성기의 **삼각형 감는 방향이 전부 반대**였다. 단면 링을 (법선, 종법선) 평면
에서 돌리고 종법선을 `접선 × 법선` 으로 잡았기 때문에, `(a, b, a+1)` 순서로 감으면
삼각형 법선이 관 **안쪽**을 향한다. 그러면 바깥에서 볼 때 앞면이 잘려 나가고 반대편
안쪽 벽이 비쳐서, 옷이 찢어지고 면이 겹쳐 보인다. 조명 계산도 뒤집혀 몸 전체가
밀랍처럼 보였다. `(a, a+1, b)` 로 바로잡아 해결했다.

비슷한 실수를 또 하지 않으려면, 새 부위를 추가한 뒤 **반드시 실제 화면에서 한 번
확인한다**. 실루엣만 보면 정상처럼 보이기 때문에 코드만 읽어서는 잘 드러나지 않는다.

### 겹치는 면을 만들지 않는다

허벅지 위에 반바지 자락을 "관 안에 관" 으로 덧씌웠더니 두 면이 거의 같은 자리에
놓여 z-fighting 으로 찢어져 보였다. 지금은 같은 중심선을 따라 **반바지 → 맨살 →
양말** 을 위아래로 끊어 이어 붙인다. 겹치는 면이 없으므로 이 문제가 구조적으로
생기지 않는다. 몸통(상의)과 골반(반바지)도 높이를 갈라 두었다.

## 텍스처 방향 규칙

원통 UV 에 글자를 얹을 때 좌우가 뒤집히기 쉽다. 뒤집기 네 조합을 등에 나란히 그려
실제 렌더로 확인한 결과는 다음과 같다.

- 캔버스에 **보이는 그대로** 그리면 옷에도 그대로 찍힌다. 캔버스의 y-down 과
  텍스처 업로드의 `flipY` 가 서로 상쇄되고, `u` 는 바깥에서 볼 때 화면 오른쪽으로 증가한다.
- `u = 0.25` 가 등 한가운데, `u = 0.75` 가 가슴이다.

`jerseyTexture` 의 `label()` 이 이 규칙을 지키는 유일한 자리이므로, 유니폼에 글자를
더 넣을 때는 그 함수를 쓴다.

## 동작 목록

서버가 `PlayerView.anim` 으로 확정해 주는 상태를 그대로 받아 그린다. 양쪽 화면이
같은 동작을 본다.

| `anim` | 화면 |
| --- | --- |
| `idle` | 숨쉬기와 무게중심 이동 |
| `run` / `sprint` | 이동 거리로 도는 달리기 사이클(발이 땅에서 미끄러지지 않는다) |
| `dribble` | 보폭을 줄이고 팔을 벌린 채 시선을 아래로 |
| `shoot` | 당기기 → 때리기 → 따라 나가기. 충전 중에는 몸이 뒤로 젖혀진다 |
| `pass` | 발 안쪽으로 미는 짧은 동작 |
| `stepover` | 발이 공 위를 바깥으로 크게 도는 원 운동 |
| `feintLeft` / `feintRight` | 상체로 체중을 한쪽에 실었다가 반대로 빠져나간다. 서버가 좌우를 따로 내려 주므로 두 값을 각각 받는다 |
| `dragback` | 발바닥으로 공을 뒤로 끌며 몸도 물러난다 |
| `tackle` | 몸을 눕히며 한 다리를 길게 뻗는 슬라이딩 |
| `prone` | 넘어져 있는 상태 |
| `celebrate` | 두 팔을 들고 가볍게 뛴다 |

개인기 동작은 서로 실루엣이 겹치지 않게 따로 만들었다. 같은 동작을 돌려 쓰지 않는다.

`AnimState` 는 서버가 원본이다. 한때 프런트 사본만 좌우를 `feint` 하나로 합쳐 두는
바람에 서버가 `feintLeft` / `feintRight` 를 보내면 어느 쪽에도 걸리지 않아 `default`
가지의 대기 자세로 떨어졌다. 사본을 고칠 때는 `app/api/src/protocol.ts` 와 값을
하나씩 맞춰 본다. 타입 검사가 로비 캡션 표에서 이 불일치를 잡아 준 적이 있다.

## 렌더러를 버릴 때

`WebGLRenderer.dispose()` 만으로는 WebGL 컨텍스트가 반납되지 않는다. 로비와 경기를
오갈 때마다 렌더러를 새로 만들기 때문에, 이것을 빼먹으면 브라우저의 컨텍스트
상한(보통 16개)에 걸려 프레임이 바닥까지 떨어진다. `MatchScene` 과 `PlayerPreview`
의 `dispose()` 는 `forceContextLoss()` 까지 부른다.
