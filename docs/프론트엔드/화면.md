# 화면

## 디자인 기준

- 스타일은 Modernist 한 갈래만 쓴다(shadcn 혼용 금지). 이모지 아이콘을 쓰지 않고,
  색·간격·글자 크기는 CSS 변수(`app/web/src/styles.css` 의 `:root`)로만 정의한다.
  새 색을 값으로 직접 쓰지 않고 반드시 토큰을 만들어 쓴다.
- 밤 경기장 분위기다. 짙은 잔디색 배경 위에 라임 계열 강조색(`--accent`)을 쓰고,
  팀 색은 왼쪽 파랑(`--team-left`) · 오른쪽 빨강(`--team-right`)으로 고정한다.
- 본문 글꼴은 Pretendard 계열 시스템 산세리프, 숫자(점수·시계)는 `tabular-nums`.
- 반응형: 900px 미만에서 로비가 세로로 접히고, 폭 720px 이하이거나 높이 520px 이하 가로
  화면이면 HUD 가 작은 화면 배치로 바뀐다(아래 "작은 화면 HUD").
  터치가 주 입력인 기기에서는 화면 조작이 나타난다.

## 렌더링 구조

경기 화면은 **three.js 로 그린 3D** 다. React 는 캔버스 한 장만 붙여 주고 그 안쪽은
`MatchScene` 이 명령형으로 관리한다. 한 화면에서 세 박자가 따로 돈다.

| 주기 | 하는 일 |
| --- | --- |
| 60fps | 3D 렌더. `SnapshotBuffer` 에서 보간된 프레임을 직접 읽는다 |
| 30Hz | 입력 전송. 렌더 루프와 **떨어진 독립 타이머**(`ui/inputPump.ts`)다. 서버의 초당 60개 제한 안쪽이다 |
| 10Hz | HUD 갱신. 사람 눈에 충분하고 React 재렌더를 아낀다 |

입력을 렌더와 떼어 놓은 이유: 예전에는 `requestAnimationFrame` 안에서 보내서 화면이
초당 15프레임으로 느려지면 입력도 초당 15번으로 떨어졌다. 지금은 GPU 쪽이 느려도 입력은
30Hz 를 지킨다. 다만 **자바스크립트 메인 스레드 자체가 막히면** 타이머도 같이 밀린다.
막힌 상태에서는 브라우저가 렌더 콜백을 먼저 돌려 타이머가 굶기 때문에, 렌더 루프도 매
프레임 `InputPump.due()` 로 "한 주기가 지났으면 보내기" 를 한다. 두 길은 같은 최소 간격
(주기 − 4ms)을 지켜 합쳐도 초당 약 34회를 넘지 않는다. 이 경우 전송 간격은 프레임 간격
만큼 늘어나며, 그것까지 없애 주지는 않는다.

- 탭이 숨으면 타이머를 세운다(숨기 직전 중립 입력은 한 번 보낸다).
- 연결이 열려 있지 않은 주기에는 보내지 않고, 한 번만 나가는 값(패스·태클·개인기·전환)은
  버린다. 재접속 뒤에 몇 초 전 누른 패스가 뒤늦게 나가지 않게 하려는 것이다.
- `seq` 는 여전히 `Connection.sendInput` 이 올린다. 보내지 않은 주기는 번호를 쓰지 않는다.

스냅샷을 React 상태로 올리지 않는 이유가 이것이다. 20Hz 로 컴포넌트를 다시 그리면
손해라서, 상태가 드물게 바뀌는 것(로비/대기/경기/종료)만 React 가 맡는다.

경기장 치수는 하드코딩하지 않는다. 접속 직후 받는 `joined.pitch`(`PitchInfo`)만 보고
짓기 때문에 서버가 규격을 바꿔도 프런트는 고칠 것이 없다.

3D 자산을 어떻게 만들고 왜 기성 모델을 쓰지 않았는지는 [3D자산](3D자산.md)에 있다.

## 조작

| 동작 | 키 | 모바일 |
| --- | --- | --- |
| 이동 | `←` `↑` `→` `↓` | 왼쪽 조이스틱 |
| 패스 | `S` | 패스 버튼 |
| 슛 | `D` (누르고 있으면 충전, 떼면 발사) | 슛 버튼 |
| 달리기 | `E` (누르고 있는 동안) | 달리기 버튼 |
| 스텝오버 | `Shift` + `↑` | 개인기 패드 위 |
| 바디페인트(좌/우) | `Shift` + `←` / `→` | 개인기 패드 좌/우 |
| 드래그백 | `Shift` + `↓` | 개인기 패드 아래 |
| 태클 | `Q` | 태클 버튼 |
| 조작 선수 바꾸기 | `C` | — |
| 시점 바꾸기 | `V` | 시점 버튼 |

`S` `D` `E` 는 동작 키다. 이동으로 처리하지 않는다(WASD 이동은 폐기됐다).

방향은 **화면 기준**으로 받는다. 카메라가 늘 내가 공격하는 골대를 보고 있으므로
`↑` 는 언제나 "상대 골대 쪽" 이다. 서버로 보낼 때만 공격 방향 부호를 곱해 월드
좌표로 바꾼다. 어느 자리에 앉아도 조작감이 같다.

개인기는 기술 이름이 아니라 **방향 벡터**(`skillDir`)를 보낸다. 앞/좌/우/뒤 중
무엇인지는 그 팀의 공격 방향을 아는 서버가 정한다. 그래야 양쪽 화면의 판정이
어긋나지 않는다.

### 입력에서 지켜야 하는 것

한 번씩 어긋나서 선수가 멈추거나 계속 달리는 일이 있었다. 지금은 이렇게 막는다.

- 방향키 keydown 은 Shift 여부와 무관하게 항상 눌림 상태에 넣는다. 개인기는 그 위에
  한 번만 얹힌다. 달리면서 스텝오버를 하는 것이 정상이다.
- 방향키를 누르고 있다가 **Shift 를 나중에 누르는 순서**도 개인기가 나간다. 이 순서가
  실제로 더 흔하다.
- 자동 반복 keydown 을 버리지 않고 눌림 상태를 다시 세운다. keyup 을 놓쳐도 다음
  반복에서 스스로 복구된다.
- 글자 입력 칸에 포커스가 있으면 **누름만** 가로채지 않는다. **뗌은 항상 처리한다**.
  방향키를 누른 채 입력 칸을 클릭하고 거기서 손을 떼도 키가 남지 않는다.
- 창을 벗어나거나 탭이 숨으면 전부 놓은 것으로 보고, 다음 전송 주기를 기다리지 않고
  **즉시 중립 입력을 한 번 보낸다**. 탭이 숨으면 입력 타이머도 멈추기 때문이다.

## 화면 구성

### 1. 로비 (`LobbyView`)

왼쪽은 경기와 **같은 모델·같은 애니메이션 코드**로 도는 3D 선수 무대다. 대기 →
드리블 런 → 스텝오버 → 왼쪽·오른쪽 바디페인트 → 드래그백 → 전력질주 → 충전 슛 →
세리머니를 차례로 보여 주고, 지금 무엇을 보여 주는지 캡션에 적는다.

오른쪽은 조작 칸이다.

- 닉네임 입력(1~12자, 제어문자 제거)
- `방 만들기` / `코드로 참가` / `혼자 연습하기`
- 초대 링크에 `?room=CODE` 가 있으면 코드 칸이 자동으로 채워진다.
- 조작 표를 항상 보여 준다.
- `그래픽` 에서 `자동` / `고화질` / `성능` 을 고른다. 고른 값은 렌더 쪽
  `three/quality.ts` 가 저장하고, 무대 선수(`PlayerPreview.setQuality`)에 바로 반영된다.

닉네임을 바꾸면 무대의 선수도 등번호·피부색·머리색이 따라 바뀐다.

### 2. 대기 (`waiting`)

6자리 코드 크게 표시 + `코드 복사` / `초대 링크 복사`, 그리고 한 팀 구성 안내
(나 한 명 + AI 동료 `teamSize - 1` 명).

### 3. 경기 (`MatchView`)

- **상단 스코어보드**: 왼쪽 닉네임 · 점수 · 남은 시간 · 오른쪽 닉네임.
  15초가 남으면 시계가 경고색으로 바뀐다.
- **카메라**: 기본은 조작 선수 뒤쪽 위에서 공격 방향을 내려다보는 3/4 시점이다.
  선수 몸이 또렷하게 보이는 것이 최우선이라 거리를 바짝 붙였고, 공이 멀어지면
  조금만 물러난다. 넓은 시야는 미니맵과 중계 시점(`V`)이 맡는다.
- **발밑 고리**: 내가 조작 중인 선수는 라임색, 패스하면 받을 동료는 노란색,
  같은 팀은 옅은 파랑, 상대는 옅은 빨강.
- **이름표**: 사람이 조작하는 선수는 닉네임, AI 동료는 역할 이름(수비/미드필더/공격).
- **하단 왼쪽 게이지**: 체력 · 슛 충전 · 개인기 쿨다운 · 태클 쿨다운. 쿨다운은
  `PitchInfo` 가 알려 준 상한으로 나눠 "준비된 정도" 로 그린다.
- **하단 오른쪽 미니맵**: 여섯 명과 공의 위치. 내가 오른쪽 팀이면 지도를 뒤집어
  내 공격 방향이 늘 화면 오른쪽이 되게 한다.
- **오른쪽 위**: 지연(ms)과 연결 상태, `시점` · `기록` · `설정` · `나가기`.
  - `기록`: 경기 중 두 팀의 슛 · 패스 성공(성공/시도 · %) · 점유율을 작은 판으로 연다.
  - `설정`: 효과음 켜기/끄기, 음량, 그래픽 품질. 모달이 아니라 버튼 아래 붙는 판이라
    경기는 멈추지 않는다. 음량 슬라이더는 손을 떼면 포커스를 놓는다(방향키가 선수로 가게).
    `Escape` 나 `닫기` 로 닫으면 포커스가 `설정` 버튼으로 돌아간다. `기록` 은 경기 중에만 누를 수 있다.
- **경기 알림**: 왼쪽 가장자리 가운데에 작은 띠로 최대 3줄, 2.6초씩. 경기장 가운데를
  가리지 않고 클릭을 가로채지 않는다. 띄우는 기준은 `game/feedback.ts` 의
  `describeEvent` 가 정한다.
  - 슛: 누가 찼든 띄운다. 사람이 조작한 선수는 닉네임, AI 는 역할 이름, 속도는 시속.
  - 패스: 내 팀 것만. AI 여섯 명의 패스를 다 띄우면 알림이 쉬지 않는다.
  - 개인기: 상대를 제쳤거나(`beat`) 사람이 직접 쓴 것만. 태클은 사람이 쓴 것만.
  - 킥오프: 휘슬과 함께 한 줄.
- **득점**: 화면 위쪽에 중계 자막처럼 `GOAL` · 넣은 팀 · 득점자(자책골 표시) · 바뀐 점수를
  2.6초 띄우고, 점수판 테두리를 넣은 팀 색으로 두른다. 예전의 화면 가운데 거대 글자는 없앴다.
- 카운트다운·상대 이탈은 경기장 위 오버레이와 배너로 알린다. 득점 자막은 위쪽, 카운트다운
  숫자는 가운데라 둘이 함께 떠도 겹치지 않는다. 화면 읽기 프로그램에는 늘 붙어 있는 숨은
  알림 칸으로 득점을 읽어 준다.
- 새 경기(재경기)가 시작되거나 재접속으로 `joined` 를 다시 받으면 지난 알림·득점 자막·
  기록을 비운다. 경기 종료 이벤트가 오면 남은 알림도 치운다.
- 모바일에서는 왼쪽 조이스틱, 오른쪽 버튼 네 개, 그 위 개인기 십자 패드가 나온다.

### 4. 종료 (`ended`)

승/패/무승부와 최종 점수, 그 아래 두 팀 **기록 비교**(슛 · 패스 성공 · 점유율, 팀 색 막대),
`재경기`(준비 인원 표시) / `나가기`.

기록은 `snapshot.stats` 의 누적값이다. 보간하지 않고 가장 최신 스냅샷 값을 쓴다. 분모가
0 이면(패스 시도 0, 점유 시간 합 0) 비율 대신 `–` 를 쓰고 막대를 그리지 않는다. 기록을
보내지 않는 옛 서버이면 표 대신 한 줄 안내가 나온다.

## 효과음

외부 음원 없이 Web Audio 로 합성한다(`game/audio.ts`). 킥(슛 세기에 따라 크기),
패스, 킥오프 휘슬, 종료 휘슬(세 번), 득점 함성.

- **기본은 꺼짐**, 켜도 작은 음량(35%)에서 시작한다. `설정` 에서 켠다.
- `AudioContext` 는 **사용자 동작 안에서만** 만들거나 깨운다. 켜 둔 설정이 저장돼 있어도
  새로고침 뒤 첫 클릭·키 입력 전에는 소리가 나지 않는다.
- 끄거나 탭이 숨으면 **울리는 중이거나 예약된 소리를 모두 멈추고(`stop`) 노드를 끊은 뒤**
  컨텍스트를 멈춘다. `suspend` 만 하면 컨텍스트 시계도 같이 서서, 예약해 둔 종료 휘슬·함성이
  다시 켰을 때 그 자리부터 이어 울렸다. 경기 화면을 나가면 같은 정리 뒤 닫는다. 정리는 여러
  번 불러도 안전하다.
- 설정은 `localStorage` 의 `sc-inter:audio` 에 둔다. 저장소가 막혀도 예외 없이 이번 판만
  기억한다.
- 같은 소리는 촘촘히 겹치지 않게 간격을 두고, 킥·패스는 동시에 8개를 넘기지 않는다
  (휘슬·득점은 상한과 무관하게 낸다). 끝난 소리는 노드 체인 전체를 끊는다.
- 사용자 동작은 `pointerdown` `pointerup` `touchend` `click` `keydown` 을 모두 본다.
  iOS Safari 가 `pointerdown` 을 동작으로 치지 않을 수 있어서다(실기기 미확인).

### 작은 화면 HUD

폭 720px 이하, 또는 높이 520px 이하 가로 화면(휴대폰 가로)에서 쓴다. HUD 는 화면 윗부분에만
두고 짧게 끝낸다. 가운데·아래는 선수 몸과 공, 터치 조작 자리다.

- 점수판 한 줄. 세로 화면에서는 폭 전체를 쓰고, 가로 화면에서는 도구줄과 같은 줄에 선다.
- 연결 칩 + `시점` `기록` `설정` `나가기` 는 **가로 한 줄 도구줄**(버튼 높이 36px).
- 게이지 네 개는 2×2 로 접고, 미니맵(104px)은 그 옆에 붙인다.
- 가로 휴대폰에서는 설정·기록 판을 오른쪽 터치 버튼(개인기·패스·슛) 왼쪽에 열어 버튼을
  가리지 않는다.
- 390×844 세로에서 HUD 아래 끝이 y199(화면의 24%), 844×390 가로에서 게이지 아래 끝이
  y155 로 조이스틱(y218~)과 겹치지 않는다(2026-09-19 측정).

## 연결이 끊겼을 때

- 지수 백오프로 최대 8번까지 다시 붙고, 그동안 배너로 알린다.
- 재접속 토큰은 `sessionStorage` 에 둔다. **새로고침해도 같은 탭이면 자리로
  돌아간다.** 탭을 닫으면 사라지고, `localStorage` 는 쓰지 않는다(다른 탭이 같은
  자리를 빼앗으려 할 수 있다).
- `나가기` 를 눌렀을 때만 서버에 `leave` 를 보내고 토큰을 버린다. 그냥 연결이
  끊긴 것과 사용자가 방을 떠난 것은 다르게 다룬다.
- 8번 모두 실패하면 전체 오버레이로 알리고 로비로 돌아갈 길을 준다.

## WebGL 을 못 쓸 때

시작할 때 WebGL 컨텍스트를 만들 수 있는지 확인하고, 안 되면 흰 화면 대신
`WebGLNotice` 로 이유와 확인할 것(하드웨어 가속, 브라우저 버전, 가상 머신)을 알린다.

## 접근성·명료성

- 모든 버튼은 버튼처럼 보이게 한다(배경·테두리·커서·포커스 링).
- 상대 이탈·연결 끊김·재접속은 경기장 위 배너로 한국어 문장으로 알린다.
- `prefers-reduced-motion` 을 켠 사용자에게는 CSS 전환을 끄고, 경기 알림·득점 자막도
  미끄러져 들어오지 않고 제자리에 바로 나타난다.

## 아직 확인하지 못한 것

정직하게 적어 둔다. 아래는 이 저장소 안에서 검증하지 않았다.

- **효과음의 실제 청감**. 자동화 환경에서는 소리를 들을 수 없어, 언제 만들고 깨우고
  멈추고 닫는지만 테스트로 확인했다. 크기·음색이 적당한지는 사람 귀로 확인해야 한다.

- **실제 터치 기기**에서 손가락으로 조작해 본 적이 없다. 데스크톱에서 터치 판정을
  임시로 켜 배치만 확인했고 그 임시 코드는 남기지 않았다.
- **두 브라우저 사이의 개인기 좌우·패스 동기화**는 통합 담당의 E2E 결과를 봐야 한다.
- **렌더 성능 수치**. 자동화 도구에서 `requestAnimationFrame` 이 1초에 0~1회로
  측정된 적이 있으나, 같은 순간 화면 캡처에는 경기와 로비가 정상으로 찍혔다.
  자동화 환경의 제약인지 실제 성능인지 가르지 못했으므로 수치를 단정하지 않는다.
  (측정 중 컨텍스트 누수를 하나 찾아 고쳤다. 위 `dispose` 항목 참고.)
