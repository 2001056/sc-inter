# 실행과 배포

## 환경변수

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `8787` | HTTP + WebSocket 리슨 포트 |
| `HOST` | `0.0.0.0` | 바인드 주소. **지금은 로컬 전용이므로 실행할 때 `HOST=127.0.0.1` 을 준다**(아래) |

값 자체는 저장소에 남기지 않는다. `.env.example` 에 이름과 안전한 기본값만 둔다.

## 지금 운영 방침: 로컬 전용 (2026-09-19 사용자 선택)

사용자는 지금은 **이 맥북 안에서만** 쓰겠다고 정했다. 그래서 개발·검증·상시 서버 모두 루프백(`HOST=127.0.0.1`)에만 바인드하고, 공개 터널·배포·외부 접속은 하지 않는다. 코드의 기본값 `0.0.0.0` 은 컨테이너용으로 그대로 두고, 로컬 실행 명령에서 `HOST` 를 명시한다. 아래 "공개 준비" 절은 나중에 사람이 따로 승인할 때를 위한 기록이다.

## 로컬 실행

```bash
pnpm install
pnpm build                # 웹 번들 + 서버 컴파일
HOST=127.0.0.1 PORT=8787 pnpm start      # http://127.0.0.1:8787
```

개발 모드(핫 리로드):

```bash
pnpm dev:api              # 8787, WebSocket + health
pnpm dev                  # Vite 개발 서버. /ws 와 /healthz 를 8787 로 프록시
```

## 상시 개발 서버 관리

에이전트 세션이 끝나도 남아 있도록 프로세스를 분리해서 띄운다.

```bash
# 시작 (프로젝트 루트에서)
mkdir -p logs
PORT=8787 HOST=127.0.0.1 nohup node app/api/dist/index.js > logs/server-8787.log 2>&1 &
echo $! > logs/server-8787.pid

# 상태 확인
curl -s 127.0.0.1:8787/healthz

# 로그 보기
tail -f logs/server-8787.log

# 중지 (기록해 둔 PID 만 종료한다)
PID="$(cat logs/server-8787.pid)"
ps -p "$PID" -o pid=,command=          # 정말 이 서버가 맞는지 먼저 확인
kill "$PID"
```

| 항목 | 값 |
| --- | --- |
| 포트 | `8787` (다른 포트를 쓰려면 `PORT` 로 바꾼다) |
| PID 파일 | `logs/server-8787.pid` |
| 로그 | `logs/server-8787.log` |

`pkill -f node …` 처럼 이름 패턴으로 죽이지 않는다. 같은 머신의 다른 프로젝트 프로세스까지 잡는다. 반드시 PID 파일의 PID 를 `ps` 로 확인한 뒤 그 PID 만 종료한다.

`logs/` 는 `.gitignore` 에 있어 저장소에 올라가지 않는다.

### 왜 이렇게 띄우는가

`nohup … &` 로 부모에서 떼어 내면 프로세스의 부모가 `init`(PID 1)이 되어, 띄운 터미널이나 에이전트 세션이 끝나도 계속 살아 있다. 살아 있는지는 이렇게 본다.

```bash
ps -p "$(cat logs/server-8787.pid)" -o pid=,ppid=,command=
# 예: 3195  1  node app/api/dist/index.js   ← ppid 가 1 이면 세션과 분리된 상태
curl -s localhost:8787/healthz
```

## 단일 프로세스 설계

`app/api` 한 프로세스가 정적 웹 파일과 WebSocket 을 **같은 origin** 으로 서빙한다. 브라우저는 현재 주소에서 `ws(s)://<host>/ws` 를 그대로 쓰므로 CORS 나 별도 도메인 설정이 필요 없다. 공개할 때도 포트 하나만 열면 된다.

## 헬스체크와 종료

- `GET /healthz` → `200 {"status":"ok","uptimeMs":…,"rooms":…,"connections":…}`
- 종료 중에는 `503 {"status":"shutting_down",…}` 을 돌려준다.
- `SIGTERM` / `SIGINT` 를 받으면 새 연결을 막고, 접속 중인 클라이언트에 `serverShutdown` 이벤트를 보낸 뒤 최대 5초 기다렸다가 프로세스를 닫는다.

## 컨테이너

```bash
docker build -t sc-inter .
docker run --rm -p 8787:8787 -e PORT=8787 sc-inter
```

`Dockerfile` 은 pnpm 으로 의존성을 설치하고 웹·서버를 빌드한 뒤, 런타임 이미지에 `app/api/dist` 와 `app/web/dist`, 운영 의존성만 담는다. 비루트 사용자로 실행하고 `HEALTHCHECK` 가 `/healthz` 를 본다. `compose.yaml` 로도 같은 구성을 띄울 수 있다.

## 공개 준비 — 정식 공개는 **아직 승인되지 않았다**

사람의 승인이 있기 전에는 아래 명령을 실행하지 않는다.

> **2026-09-18 사고**: 문서를 쓰는 과정에서 셸 인용 실수로 이 명령이 의도치 않게 한 번 실행되어, 약 2분 동안 임시 공개 주소가 살아 있었다. 즉시 종료했고 정식 공개는 여전히 승인되지 않았다. 경위는 [`../핸드오프/202609/2026-09-18-백엔드와-통합.md`](../핸드오프/202609/2026-09-18-백엔드와-통합.md) 의 사고 기록에 있다.

### 임시 공개(계정 없이) 후보: Cloudflare Quick Tunnel

로컬에 도구만 설치해 두었다. 설치와 버전 확인은 되돌릴 수 있는 준비 작업이고, 터널을 여는 것은 별개다.

```bash
cloudflared --version     # 확인됨: 2026.9.1 (2026-09-10 빌드), /opt/homebrew/bin/cloudflared
```

승인 후 실행할 **단 한 줄**은 다음과 같다.

```bash
cloudflared tunnel --url http://localhost:8787
```

- 전달 대상: **이 게임 서버의 8787 포트 하나**다. 이 명령은 그 포트로만 트래픽을 넘긴다.
- 계정·로그인·도메인이 필요 없다. 프로세스를 끝내면 터널이 끊어져 그 주소로는 더 이상 서버에 닿지 않는다. 다만 "주소가 즉시 사라진다"고 보장할 수는 없다. 종료 뒤 실제로 응답이 끊겼는지는 그때 직접 확인한다.
- 주소는 무작위 `https://….trycloudflare.com` 이고 HTTPS 라서 브라우저가 `wss://` 로 붙는다. 서버가 같은 origin 으로 웹과 WebSocket 을 모두 주므로 추가 설정이 없다.
- 주소를 아는 사람은 누구나 들어올 수 있고, 서버에는 요청 로그가 없어 누가 들어왔는지 알 수 없다. 그래서 사람의 승인 없이는 열지 않는다.

### 그 밖에 남은 것

- 실제 배포(클라우드/서버 업로드), 도메인·TLS 설정.
- 리버스 프록시를 둘 경우 WebSocket 업그레이드 헤더(`Upgrade`, `Connection`) 통과 설정이 필요하다.
