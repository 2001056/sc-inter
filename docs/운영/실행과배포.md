# 실행과 배포

## 환경변수

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `8787` | HTTP + WebSocket 리슨 포트 |
| `HOST` | `0.0.0.0` | 바인드 주소 |

값 자체는 저장소에 남기지 않는다. `.env.example` 에 이름과 안전한 기본값만 둔다.

## 로컬 실행

```bash
pnpm install
pnpm build                # 웹 번들 + 서버 컴파일
PORT=8787 pnpm start      # http://localhost:8787
```

개발 모드(핫 리로드):

```bash
pnpm dev:api              # 8787, WebSocket + health
pnpm dev                  # Vite 개발 서버. /ws 와 /healthz 를 8787 로 프록시
```

## 상시 개발 서버 관리

에이전트 세션이 끝나도 남아 있도록 프로세스를 분리해서 띄운다.

```bash
# 시작 (프로젝트 루트에서)
mkdir -p logs
PORT=8787 HOST=0.0.0.0 nohup node app/api/dist/index.js > logs/server-8787.log 2>&1 &
echo $! > logs/server-8787.pid

# 상태 확인
curl -s localhost:8787/healthz

# 로그 보기
tail -f logs/server-8787.log

# 중지
kill "$(cat logs/server-8787.pid)"      # 또는: pkill -f "node app/api/dist/index.js"
```

| 항목 | 값 |
| --- | --- |
| 포트 | `8787` (다른 포트를 쓰려면 `PORT` 로 바꾼다) |
| PID 파일 | `logs/server-8787.pid` |
| 로그 | `logs/server-8787.log` |

`logs/` 는 `.gitignore` 에 있어 저장소에 올라가지 않는다.

## 단일 프로세스 설계

`app/api` 한 프로세스가 정적 웹 파일과 WebSocket 을 **같은 origin** 으로 서빙한다. 브라우저는 현재 주소에서 `ws(s)://<host>/ws` 를 그대로 쓰므로 CORS 나 별도 도메인 설정이 필요 없다. 공개할 때도 포트 하나만 열면 된다.

## 헬스체크와 종료

- `GET /healthz` → `200 {"status":"ok","uptimeMs":…,"rooms":…,"connections":…}`
- 종료 중에는 `503 {"status":"shutting_down",…}` 을 돌려준다.
- `SIGTERM` / `SIGINT` 를 받으면 새 연결을 막고, 접속 중인 클라이언트에 `serverShutdown` 이벤트를 보낸 뒤 최대 5초 기다렸다가 프로세스를 닫는다.

## 컨테이너

```bash
docker build -t sc-inter .
docker run --rm -p 8787:8787 -e PORT=8787 sc-inter
```

`Dockerfile` 은 pnpm 으로 의존성을 설치하고 웹·서버를 빌드한 뒤, 런타임 이미지에 `app/api/dist` 와 `app/web/dist`, 운영 의존성만 담는다. 비루트 사용자로 실행하고 `HEALTHCHECK` 가 `/healthz` 를 본다. `compose.yaml` 로도 같은 구성을 띄울 수 있다.

## 아직 하지 않은 것 (사람 승인 필요)

- 실제 배포(클라우드/서버 업로드), 공개 터널, 도메인·TLS 설정.
- 리버스 프록시를 둘 경우 WebSocket 업그레이드 헤더(`Upgrade`, `Connection`) 통과 설정이 필요하다.
