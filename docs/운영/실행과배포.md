# 실행과 배포

## 환경변수

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `8787` | HTTP + WebSocket 리슨 포트 |
| `HOST` | `0.0.0.0` | 바인드 주소 |

값 자체는 저장소에 남기지 않는다. `.env.example` 에 이름과 안전한 기본값만 둔다.

## 로컬

```bash
pnpm install
pnpm build
PORT=8787 pnpm start     # http://localhost:8787
```

개발 모드(핫 리로드):

```bash
pnpm dev:api             # 8787
pnpm dev                 # 5175, /ws 와 /healthz 를 8787 로 프록시
```

## 단일 프로세스 설계

`app/api` 한 프로세스가 정적 웹 파일과 WebSocket 을 **같은 origin** 으로 서빙한다. 브라우저는 현재 주소에서 `ws(s)://<host>/ws` 를 그대로 쓰므로 CORS 나 별도 도메인 설정이 필요 없다.

## 헬스체크와 종료

- `GET /healthz` → `200 {"status":"ok","uptimeMs":…,"rooms":…}`
- `SIGTERM` / `SIGINT` 를 받으면 새 연결을 막고, 접속 중인 클라이언트에 종료를 알린 뒤 최대 5초 기다렸다가 프로세스를 닫는다.

## 컨테이너

```bash
docker build -t sc-inter .
docker run --rm -p 8787:8787 -e PORT=8787 sc-inter
```

`Dockerfile` 은 pnpm 으로 의존성을 설치하고 웹·서버를 빌드한 뒤, 런타임 이미지에 `app/api/dist` 와 `app/web/dist`, 운영 의존성만 담는다. 비루트 사용자로 실행하고 `HEALTHCHECK` 가 `/healthz` 를 본다.

## 아직 하지 않은 것 (사람 승인 필요)

- 실제 배포(클라우드/서버 업로드), 공개 터널, 도메인·TLS 설정.
- 리버스 프록시를 둘 경우 WebSocket 업그레이드 헤더 통과 설정이 필요하다.
